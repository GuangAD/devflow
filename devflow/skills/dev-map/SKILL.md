# dev-map — 决策地图

前提认知:**地图产决策,不产代码;产代码是 /dev 的事。** 一个需求大到一次访谈装不下、且有些区域连问题都还说不出 sharp 时,直接进 /dev 会被门 1 的自查红线卡死——那条红线是"开放问题非空不得呈报",而巨大需求的本质恰恰是开放问题短期清不空。地图层就是为了让"说不清的雾"变成"已定决策"而存在。

## 什么时候不该用

- 设计树一轮能收、没有说不出 sharp 的区域 → 这是"重"不是"巨",直接 /dev。
- 建地图的第一次广度扫描**没扫出任何雾** → 停下告诉用户不需要地图,问他怎么走(进 /dev 重流程,还是就地聊完)。

## 地图

地图是单个 Markdown 文件 `docs/maps/<YYYY-MM-DD>-<slug>/map.md`,进 git。它是**索引不是仓库**:每条决策只存在它自己的票里,地图只存一行 gist,不复述结论。

按 [references/map-template.md](references/map-template.md) 创建,五节:目的地 / 备注 / 已定决策 / 雾 / 越界。

**目的地先定。** 目的地定死范围,越界的关掉。它一两行,每个会话开工前先读它再选票——它决定这张票该不该存在。

## 票

票是 map.md 里的条目,一行一张,状态用 checkbox,解完回填 commit 哈希(与 plan.md 同一套记账法)。票的问题全文与结论写在条目下方。

四种类型,标注在票名后:

- **调研**(AFK):查文档、第三方 API 或代码库才能拿到的事实,某个决策正等它。派子代理干,不占用户。
- **原型**(HITL):把讨论的保真度提上去——一个粗糙但具体的东西让人反应。用于"它该长什么样/该怎么表现"才是关键问题时。
- **访谈**(HITL):默认类型。调 grilling + domain-docs。**agent 不许替用户回答自己的问题**——自己问自己答的访谈已经坏了。
- **任务**(HITL 或 AFK):本身不是决策,但某个决策被它堵住——注册一个服务才能评判它的 API,搬一次数据才看得见形状。它靠"解锁某个决策"挣到位置,不是靠交付目的地。

## 雾

地图**故意不完整**:能看清多远画多远。

**雾还是票?判据是:你现在能不能把这个问题说精确,而不是你现在能不能回答它。**

- 能说精确 → 开票,哪怕它还被别的票阻塞着、眼下动不了。
- 还不能说 sharp → 留在雾里。**别把雾预先切成票大小的块**:雾比票粗,一块雾等前线推到它时可能毕业成几张票,也可能一张都不成。

解完一张票会照亮它前面的雾一块;毕业出来的新票当场开出来,并把那块雾从「雾」节清掉——同一件事只活在一个地方。

## 越界

雾只朝目的地聚。超出目的地的不是雾,归「越界」节:这次明确不做的。越界的永不毕业,除非目的地被重画——那时它是新的一次努力,不是续集。

已经开的票若被发现其实在目的地之外(建图时划错,或被某个结论照出来),**关掉它**(关掉的票确定不在前线上),在「越界」节留一行 gist 加原因并链过去。它不进「已定决策」——那是记录实际走过的路,范围边界不是路上的一步。

## 调用

两种模式。**每会话最多解一张票**,调研票除外(可并行)。

### 建地图

1. **定目的地**:调 grilling + domain-docs,钉死这张图要走到哪——一份规格、一个要先锁的决定,还是一次就地改造。目的地定范围,所以它先定。
2. **扫前线**:再访谈一轮,这次**广度优先**——在整个空间上铺开,不在任何一条线上钻深,把现在能动的决策和第一步浮出来。没扫出雾就按上面「什么时候不该用」停下。
3. **建地图**:目的地与备注填好,已定决策空着,雾描进「雾」节。
4. **开现在能说精确的票**,再**第二遍**接依赖(票得先有编号才能互相引用)。接完就分出前线与被阻塞的;说不清的留在雾里。
5. **放调研子代理**:每张调研票派一个子代理去解,结论记回票上。
6. 停:建图是一个会话的活,不现场解任何票。

### 走地图

1. 读 map.md(低分辨率视图,不是所有票的详细内容)。
2. 选票:用户点名就用它,否则取前线第一张。**先认领再动手**——把该票标为进行中。
3. 解它。需要时再拉相关票的详情;拿不准就调 grilling + domain-docs。
4. 记结论:勾选该票、把答案 gist 写进「已定决策」节、提交并回填 commit 哈希。
5. 补票:新浮出来的开票;被照亮的雾毕业成票并从雾节清掉;若某张票被发现在目的地之外,按「越界」处理;若这个结论让地图别处失效,更新或删掉那些票。

**认领是 git 降级版**:没有 tracker 的 assignee,靠"每会话一票 + 解完即提交"防并发撞车。多个会话并行时各自挑不同的票,开工前先看一眼地图有没有被别人改过。

## 出口

**雾散、前线空了,地图就走完了。** 此时把「已定决策」全部汇总,进 /dev 走重流程:design.md 从已定决策直接生成,访谈只补门 1 自查发现的具体空白。

地图留在 `docs/maps/` 不删:目的地与越界的取舍是"当时为什么这么定"的第一手证据。

## 纪律

- 地图不改代码。想动手的冲动通常是信号:你已经走到地图边缘,该交接给 /dev 了。
- 提到票就说名字,不说编号:一面墙的 `#42 #43` 读不了。
- 已定决策只可被取代、不可就地修改(同 ADR):被推翻时在「已定决策」追加一行并注明取代了哪一行,保留完整推理链。
- 全程同时执行 domain-docs 技能:术语当场写入 CONTEXT.md,够格的决策当场写 ADR。
