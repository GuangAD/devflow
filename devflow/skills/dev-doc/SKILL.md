# dev-doc — 知识沉淀

独立沉淀入口,与 dev 重流程内置的是同一套纪律。执行时读取 domain-docs 技能并严格遵守其格式与门槛——本文件只是路由入口,纪律的单一真值在 domain-docs,此处不复述。

## 步骤

1. **确定沉淀对象**,按用户参数,没有参数则问:这次要沉淀什么?常见三类:
   - 一个术语要定义/锐化/纠正(会话中刚聊清楚的)
   - 一个决策要记 ADR(刚拍板的难逆转选择)
   - 从当前会话提取:检索本会话,列出所有"已落定但未记录"的术语与决策,供用户挑选
2. **核对门槛**:术语 → 与现有 CONTEXT.md 查重查冲突;ADR → 三条件(难逆转+缺上下文会令人困惑+真实权衡)全满足才写,不满足的要向用户说明为什么不写。
3. **写入**:按 domain-docs 的格式写入 CONTEXT.md 或 `docs/adr/NNNN-<短名>.md`。ADR 编号查现有文件递增。
4. **回报**:列出本次新增/修改的词条与文件路径。

## 注意

- ADR 只在用户认可决策内容后写入;用户只是随口提了一个选项,不算决策。
- 术语定义必须与代码库现实交叉验证过(代码做不到的"语义"要指出差异,由用户裁决以哪个为准)。
- 取代旧 ADR 时:旧文件状态改"已被 NNNN 取代",不删除、不改写其正文。
