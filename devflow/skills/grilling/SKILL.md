# grilling — 访谈原语

把用户的想法访谈成一份没有含糊分支的共识。固定采用**整轮**，不切换为逐个提问，不设问题数量上限或下限。

## design tree、round 与 frontier

把讨论建模为一棵 **design tree**：每个决策分支出挂在它下面的子决策。根是「要做什么」，往下分出方案选择、边界行为、优先级等分支。

按 round 工作。每一轮的 **frontier** = 所有前置条件已落定、现在就能问的问题。

- 一轮提出**当前不依赖其他未答问题的全部问题**，不是把整棵树上能想到的未来问题一次倒出来
- 同一轮内互相依赖的问题，靠后的属于下一轮，不硬塞
- 每题编号并附**推荐答案**，措辞让「是」等于接受推荐
- 用户回答会解锁下游问题 → 重新计算 frontier，进入下一轮
- 访谈结束时，影响方向的分支都不能被默默假设

格式：

```
❓ Q1 - <问题标题>:<题干>

➡️ <推荐答案与一句理由>

---

❓ Q2 …
```

写「模糊匹配我打算做成输一部分就能匹配，对吗？」而不是「你想用哪种匹配方式？」。

用户可以逐条、整轮接受（「都按你推荐的来」）、部分回答或跳过。答不了的留在树上，下一轮再问；也可以明确说「够了」。

## 每轮循环

```text
提出完整一轮
  ↓
用户回答
  ↓
回述本轮新增或改变的决定，指出冲突与新缺口
  ↓
重新计算 frontier
  ├─ 还有问题 → 再提出完整一轮
  ├─ 没有问题 → 回述整份共识，等用户确认
  └─ 用户说够了 → 停止提问，处理剩余欠账
```

从第二轮起，一轮消息先回述上一轮，再列下一轮问题。

**回述只写上一轮新增或改变的决定，通常 1-5 条，能一句说清就一句；不重复此前已确认且没有变化的内容。** 上一轮只确认一个细节，就只回述那一条。

回述中，只有用户说过的算用户决定；agent 补的写成「我的提案」或 `[我]`。每轮回述都问「哪里不对、漏了什么」。

最后一轮才完整回述一次共识：目标、非目标、失败形态、选定方案、关键约束、未定项与授权项、验收口径。长度以用户能检查理解是否有错、是否有漏为准，不设固定字数。

## 先过滤，只问该问的

| 类别 | 例子 | 处置 |
|---|---|---|
| **用户的事** | 搜不到时显示什么、要不要支持错别字容错、先做哪个 | 必须问 |
| **我的事** | 函数叫什么、放哪个目录、用哪个库、内部怎么拆 | 自己定，在文档里标 `[我]` |
| **代码的事** | 现在怎么跑的、有没有现成的、项目定过什么规矩 | 自己查，不许问 |

一轮里如果后两类占了多数，说明事实查得不够，回去补。

## 分工铁律

- **事实是你的活**：frontier 问题需要代码库或环境事实时，自己去查或派 subagent，绝不反问用户任何「查一下就知道」的东西。探索未完成只阻塞其下游问题，其余照常问。
- **决策是用户的活**：每个影响方向或交付结果的决策点都要交付给用户并等待回答。禁止自己替用户拍板这些决策。
- **自己做的选择必须标出来**：凡是自己拍的决定，写成「我的判断」，**绝不许写成「用户同意过的」**。

## 什么时候停

结束条件不是问题数量归零，而是：

> **影响方向的未知已经清零；其余未知要么有承接，要么用户明确授权 agent 处理。**

- 剩下的只影响「怎么做」，不影响「做什么」→ 停
- 剩下的答错了可以事后调 → 停
- 剩下的不定就做不下去 → 继续问

用户说「够了」不等于所有问题已解决：

- 局部级未知 → 写入 brief 第 6 节「未定项」，或经明确授权写入第 8 节「授权项」
- 结构级未知仍未清 → 不能过门 1；必须缩小范围、列为非目标，或先定这一项

结构级问题指：不定下来就无法确定任务边界、数据结构或验收方式的问题。

## 没缺口就不访谈

用户给的文档已经写全、和代码现实对得上、没有冲突项 → 直接说「我看明白了，这就去做」，跳过访谈。

## 结束与确认

frontier 为空时，向用户完整回述共识，**等用户确认达成共识**。确认之前不写 brief、不碰任何代码。

用户中途改变想法或给出否定前面某轮答案的新信息时：更新 design tree 上受影响的分支，重算 frontier，把受波及的已「定」决策重新交付确认。
