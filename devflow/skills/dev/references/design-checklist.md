# 设计自查清单

写 design.md 与 spec.md 骨架之前过一遍;门 1 呈报之前再过一遍。任何一条不过,视同「开放问题非空」,不得呈报门 1。条目来源:历史项目评审发现的缺陷教训——每个新项目的变更记录若暴露同类缺陷,应回填为新条目。

- [ ] 每个 seam 接口条目四件套齐备:签名 / 后置条件 / 副作用与可重入性 / 错误行为。
- [ ] 宣称「连续 / 环回 / 单调」的接口,枚举了性质作用的字段清单与容差。(教训:环回断言曾仅锁 11 字段中的 5 个,评审才补全)
- [ ] 有状态类与工厂(含非 seam 导出)写明重用语义:重复调用是清空还是累加。(教训:builder 复用未清空缓冲区,几何翻倍,复审才抓到)
- [ ] 每个 seam 接口至少 1 条 pinned case,期望值声明事实源;禁止用被测代码同样算法重算期望值。
- [ ] 接口面穷举清单覆盖全部模块的公共导出;不允许「整层只靠一句模式约定」。(教训:某工具模块整文件未入设计,seam 清单事后过期只能散文补注)
- [ ] 数据注册表(占位/waiver/白名单类常量集合)定义了 schema 与准入规则,并规划钉住其规模的测试(如 waiver 表长度断言)。
- [ ] 架构图(若有)与文字鸟瞰一致:图节点与模块清单一一对应,图只承载关系与流向、不复述文字职责;图属 design.md 冻结范围,开发期修订走回退协议,不就地改图。
- [ ] 数值预算(性能/规模/体积)逐条有机检方案:测试断言或构建期脚本;不接受「运行时打印人工核对」。
- [ ] 事实数据只进数据模块,渲染与 UI 层零硬编码;计划外新建数据模块必须回填穷举清单。
- [ ] 技术栈新增依赖在 design.md 权衡节有理由;与既有依赖不重复(同类功能已选 A 不引 B)。
- [ ] spec.md 未夹带 design.md 未覆盖的决策;切任务或写规格时暴露设计空白 → 停下回访谈,不就地拍板。
