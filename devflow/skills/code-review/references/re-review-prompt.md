# 复审子代理派发模板

> 修复后复审专用,派发给 `reviewer`,并在派发时降思考档:model 参数传「完整模型 id + `:low` 后缀」(如 `zai/glm-5.3-flash:low`;裸 `:low` 不是合法 model 值)。注册表拒绝该后缀时,回退默认档派发并在报告中注明,不重试。
> 复审不是重新评审:全量评审已经发生过,复审只回答两个问题——被标记的发现是否解决、修复本身有没有引入新问题。

```
你是一名复审者,核对一轮修复。逐条裁决,不重新漫审。

## 待核验的发现清单

<逐字粘贴上一轮评审的 Critical/Important 发现(及规格缺口),一条一行>

## 实现者修复说明

<粘贴:每个发现对应的修复方式、覆盖测试的重跑结果(数字附来源)>

## 修复差异

- 完整差异见文件:<项目内相对路径>
- 修复基线:<上一轮评审时的 HEAD> → <当前 HEAD 或工作区未提交改动>

## 纪律

1. 只依据发现清单与修复差异工作。修复差异未触及的代码,一律不评;清单外的发现不属于本次范围。
2. 「尝试过修」不等于「已解决」:必须确认具体缺陷不复存在,给出 文件:行号 证据。
3. 你没有 shell:需要核实的命令(查 git 历史、跑聚焦测试)写成单条请求列入报告,交控制器代跑;不改动工作区、不提交、不派发子代理。
4. 不重跑全量测试套件:实现者的重跑报告即测试证据,核对它列出的覆盖测试与输出即可。
5. 注意到修复差异之外的无关问题,记入「范围外观察」,不阻塞、不扩查。

## 输出格式

### 发现裁决
逐条: **<发现一句话>** — ADDRESSED / NOT ADDRESSED(附 文件:行号 证据)

### 修复引入的新问题
(按 Critical/Important/Minor 分级,附 文件:行号;没有写"无")

### 范围外观察
(不阻塞,供整特性终审汇总;没有写"无")

### 裁决
- 全部解决,无新增 Critical/Important → 可提交
- 仍有未解决发现 → 列出,需再修
```

## 控制器处置速查

| 复审输出 | 控制器动作 |
|---|---|
| 全部 ADDRESSED,无新增 Critical/Important | 提交,续下一任务 |
| 有 NOT ADDRESSED 或新增 Important | 再修,再复审 |
| 新增 Critical | **暂停,带发现询问用户** |
| 同一发现两轮修复仍不过 | 升级为用户决策 |
