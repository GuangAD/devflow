# devflow 技能:seam 用例三层模型(钉住用例 / 覆盖声明 / 实现期兑现)

## 目标

解决「3~8 条用例覆盖不了复杂计算边界」的问题。分工定为:

- **用例表 3~8 条**:人审契约锚点,定规则(不变);
- **覆盖声明**(新增):等价类矩阵 + 机检铁律 + 枚举范围,门 2 批准「测到什么程度算全」;
- **实现期照单兑现**(tdd 纪律):生成器 + 铁律断言,发现维度漏项走变更记录回填;
- **评审按单审计**(code-review 对照物):加上覆盖声明。

**1b.** pinned case 表格后(line `fhCC`,空行)插入覆盖声明块:

```markdown
- **覆盖声明**(门 2 前必答;定义「测到什么程度算全」,实现期照单兑现):
  - **等价类矩阵**:行为的维度分解与组合代表。先列维度与取值,组合有限时逐组合一行;`| 维度/组合 | 代表输入 | 期望要点 |`。矩阵行是实现期必测项。
  - **机检铁律**:不逐例写期望值的独立断言(往返 / 守恒 / 幂等 / 字符集 / 结构不变式),每条注明 oracle 为何独立——逆方向实现算独立(如把输出解析回输入再比对),用同算法重算不算。
  - **枚举范围**:交给机器生成的输入空间与验证方式(如「4 位段 0~9999 全枚举 + round-trip」「随机 1000 组输入 + 守恒断言」)。
  - 简单接口无可声明项时,写「无——用例表即全量」并一句理由;组合边界只靠矩阵代表盖不住的,必须配枚举或铁律。
```

### 2. tdd/SKILL.md

**2b.** mutation check 节之后、「卡住对照表」之前插入新节:

```markdown
## 覆盖兑现与回填

spec.md 的覆盖声明(等价类矩阵、机检铁律、枚举范围)是门 2 批准的覆盖标准,实现期照单兑现:

1. **矩阵逐行有测试,铁律有断言,枚举有生成器**。枚举不是手写几万条 it(),是生成代码循环断言;铁律的 oracle 与被测实现必须方向独立(逆方向实现,如 round-trip 解析器;同算法重算不算)。
2. **生成器与铁律创建时验证一次鉴别力**:临时改坏一行实现,枚举或铁律必须转红;全绿说明断言空心,对照三种反模式重写。为钉住缺陷补写的矩阵行,走上面的 mutation check。

```
